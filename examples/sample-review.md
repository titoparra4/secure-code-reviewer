### SCR-0003 — Insecure Direct Object Reference on invoice retrieval

| Attribute | Value |
|---|---|
| Severity / Confidence | High / High |
| Status | Confirmed |
| Remediation priority | P1 (effort: Low) |
| CWE | [CWE-639](https://cwe.mitre.org/data/definitions/639.html) |
| OWASP | A01:2021-Broken Access Control; API1:2023-Broken Object Level Authorization |
| Location | `app/app.py:41-46` |
| Source | agent (rule `agent.insecure-direct-object-reference-on-invoice-retrieval`) |

**Evidence (sanitized)**

```py
cur.execute("SELECT * FROM invoices WHERE id = ?", (invoice_id,))
return jsonify(cur.fetchone())
```

**Technical explanation.** The handler loads an invoice by the path parameter invoice\_id and returns it without checking that the invoice belongs to the authenticated user. No authorization decorator or ownership filter exists on this route or in a before\_request hook (reviewed app/app.py in full).

**Potential impact.** Any user who can reach the endpoint can enumerate invoice ids and read other customers' invoices (personal and financial data).

**Exploitation conditions.** Trivial when invoice ids are sequential; requires only network access to the endpoint.

**Business impact.** Exposure of customer financial data; likely reportable privacy incident.

**Recommended fix.** Scope the query to the current user (WHERE id = ? AND owner\_id = ?) and return 404 when the invoice is not owned by the caller. Centralize the check in a reusable authorization helper.

**Corrected code (illustrative example; adapt to the project's language and framework).**

```
cur.execute("SELECT * FROM invoices WHERE id = ? AND owner_id = ?", (invoice_id, current_user.id))
row = cur.fetchone()
if row is None:
    abort(404)
```

**Security test.** With two local test users A and B, request B's invoice id as A and assert 404 and no invoice data in the body.

**Regression test.** Assert that A can still read A's own invoice (200, same payload as before).

**Verification status.** Confirmed — method: manual, reproduced: no (confirmed by code reading; no dynamic test executed). To verify the fix: Run both tests; review the other object-returning routes for the same pattern.
